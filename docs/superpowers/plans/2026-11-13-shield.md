# Shield implementation plan

> **For agentic workers:** Execute inline with superpowers:executing-plans.
> Keep progress here; verify each task before proceeding.

**Goal:** Ship an automatic one-charge shield with brief escape protection and
correct exact minimums for fixed-spike shortcuts.

**Architecture:** The game model owns shield and damage state. The existing
slide graph gains pickup/armed/spent inventory states; collection search reuses
those vertices. The generator places one pickup and verifies the final board.
Rendering and terminal acceptance expose the new behavior.

**Tech stack:** Existing Rust 1.75, rand, crossterm, and Python standard library.

**Spec:** [Shield rules](../specs/2026-11-13-shield-design.md).

## Global constraints

- Preserve 80x24 terminals, deterministic finite generation, intact templates,
  safe waiting cells, and exact ANY% and 100% slide minimums with forgiving pars.
- One optional pickup per stage, no score or 100% collection requirement.
- Damage consumes the shield and protects only the current slide.
- No dependencies or carryover between stages. Leave changes uncommitted for review.

## Review focus

- Adjacent spikes and activation underneath the player must consume only one charge.
- Spent pickups must never rearm a shield on backtracking.
- Inventory state must participate in BFS parents and full-clear dominance.
- Newly reachable stops must still be safe to wait on.
- Shield and legend text must fit at 80x24; retry/pause/resize must preserve their rules.
