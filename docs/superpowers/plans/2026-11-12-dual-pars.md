# Dual completion pars

Implement the user's requested ANY% and 100% pars in the existing random-stage game.

## Rules

- ANY% is the minimum safe slide count to enter the exit.
- 100% is the minimum safe slide count to collect every dot and coin and then enter the exit. The exit still ends a run immediately.
- Individual reward reachability does not prove a full-collection run exists. Accept a generated stage only after both objectives have exact solutions.
- Keep exact full-collection search bounded. Reject an unproved generation candidate on exhaustion; never display an estimate as par.
- Retain seeded replay, map usefulness, difficulty ranges for ANY%, and existing controls.

## Implementation

- [x] Extend the existing slide solver to retain direction-labelled edges. Search resting position plus collected reward groups in breadth-first order. Rewards always collected by exactly the same edges can share a bit. At the same resting position, an earlier state with a superset of collected rewards dominates a later subset. Return a shortest witness route or an explicit impossible/budget result.
- [x] Pin both objective semantics with hand-checked maps, including terminal-exit traps, dots and coins crossed in transit, revisits, no rewards, spikes, and budget exhaustion.
- [x] Replace Stage.par with Stage.pars containing any_percent and full_clear. Compute both after reward placement and retry generation candidates without changing terminal rules.
- [x] Display both labelled pars in the existing HUD. Document 100% as all dots and coins. Preserve the 80x24 layout.
- [x] Verify full-clear witness routes through the actual Game, check independent minimal search on small fixtures, rerun seeded generation batches, format/lint/build, and extend the PTY check to see both HUD values.
